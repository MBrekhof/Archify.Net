# Archify C# Port — Phase 5: the `archify` CLI

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A `dotnet tool` named `archify` that behaves like upstream `bin/archify.mjs` for these commands:
`render validate check deliver finalize browser-check visual-check guide inspect examples doctor demo`, plus `install-browser`.

"Behaves like" means the same messages, exit codes, JSON receipts (minus `update`), sidecars, lock and journal. The
phase-5 exit has two parts:
- `archify finalize` passes on every example;
- the web-app receipts equal upstream's field by field, once nondeterministic fields are normalised.

**Architecture:** Two new projects.
- `src/Archify.Net.Cli` is the tool (`PackAsTool`, `ToolCommandName archify`).
- `tests/Archify.Net.Cli.Tests` holds its tests.

The library `Archify.Net.Core` gets a few seams (Task 2) and stays dependency-free and lexical (spec decision S6).
- Everything filesystem-shaped lives in the CLI: native paths, path semantics, output-path resolution, sidecars, lock,
  journal, receipts.
- The CLI runs **in one process**. Upstream's child processes become calls, the checker is `ArchifyNet.Check`, and the
  browser is Playwright.
- The in-process entry point is `Cli.Run(string[] args, CliIo io) → int`, testable without spawning. `Program.Main` is a
  thin shell around it.

**Tech Stack:** .NET 10, C# 14. `Microsoft.Playwright` 1.63.0 is the CLI project's only package (Chromium 153,
revision 1243). xUnit 2.9.3. Node 24 and git are used at dev time to mint expected values from upstream
`C:\projects\archify` @ `c21c31ff`.

**Spec:** `docs/superpowers/specs/2026-10-13-archify-csharp-port-design.md`, "## CLI" and porting-order step 5. Where
the spec and upstream disagree, the plan follows upstream; Q4 and Q5 list each case. The three surveys below are probe-backed
and every implementer reads the ones named in their task **in full**:
- `.superpowers/sdd/2026-10-15-phase5-cli/survey-cli.md` (command surface)
- `.superpowers/sdd/2026-10-15-phase5-cli/survey-delivery.md` (deliver, finalize, sidecars, lock, journal, path semantics)
- `.superpowers/sdd/2026-10-15-phase5-cli/survey-browser.md` (browser-check, visual-check, Playwright, test inventory)

- **Q2 — in-process I/O contract.**
  - `CliIo(TextWriter Stdout, TextWriter Stderr, string Cwd, CliServices Services)`. `CliServices` holds the seams:
    - `IBrowserInspectorFactory`;
    - `Func<Guid>` for receipt ids;
    - `Func<DateTimeOffset>` for clocks;

  - `Program.Main` sets `Console.OutputEncoding = new UTF8Encoding(false)`, wraps stdout and stderr in writers with
    `NewLine = "\n"`, calls `Cli.Run` and returns its code.
- **Q3 — command-surface rulings** (ledger):
  - The CLI reads **no** `ARCHIFY_*` environment variable. `--quality` and `--repo-root` map onto `RenderOptions`.
  - **No System.CommandLine.** Dispatch is a hand-port of A:7059-7138, so every message, check order and exit code (0/1/2)
    is upstream's.
  - `examples` writes to `<cwd>/examples/`.
  - `doctor` checks the .NET runtime, the embedded resources, git on PATH and the Playwright Chromium install, in
    upstream's `[ok|missing|invalid]` line format and with upstream's exit contract.
  - Help text is upstream's `usage()` minus the four OUT commands (`compare`, `brands`, `migrate`, `preview`) plus the
    line `  archify install-browser`, placed directly after the `doctor` line. The OUT commands answer `Unknown command`,
    exit 2.
    - `usage()` text also appears inside other outputs: `cli/usage` receipts (in `error` and `diagnostics[0].message`)
      and the stderr of human arity errors.
    - Tests therefore apply **one** shared helper, `UsageEdit.Apply(string)` in the test project, to every fixture before
      comparing.
    - `install-browser --help` is not minted from Node, because upstream has no such command. It is tested directly
      against the edited `usage()`.
  - **Stated deviation:** help, env vars, the examples location, doctor's checks.
- **Q4 — browser rulings** (ledger; overrides card and spec):
  - `browser-check` and `visual-check` port **upstream's measurement gate**: 6 inspections (4 light, 2 dark),
    containment, readability ≥ 6 px projected text, Dock clearance, theme resolution, and the receipt shape of survey-browser §1.
    The upstream settle and metrics scripts (VC:1603-1633, VC:1635-1799) are embedded **verbatim** as resources and run through
    Playwright `EvaluateAsync`, deserialised into typed records. (`EvaluateAsync<JsonElement>` adds `$id` keys.)
  - Browser: pinned Playwright Chromium only, launched headless at device scale factor 1, with no system-Chrome fallback.
  - A missing browser executable is upstream's "Chrome unavailable" path: status `skipped`, exit 2, a `viewer/chrome-unavailable`
    warning whose `supportedFixes` names exactly `archify install-browser`.
  - `archify install-browser` runs `Microsoft.Playwright.Program.Main(["install", "--only-shell", "chromium"])` in-process.
  - The receipt keeps upstream's `chrome{status,executable}` key names; `executable` is Playwright's path.
  - visual-check PNG bytes are **not** golden-compared, because they depend on the browser build. Tests check:
    - the file set;
    - PNG magic and IHDR dimensions;
    - the receipt shape;
    - the sheet and receipt text, with hashes masked.
- **Q5 — delivery rulings** (ledger; overrides spec):
  - finalize = deliver → check → browser-check (finalize.mjs:809). The validate gate is synthesised from the deliver receipt,
    and the default is `--quality showcase`.
  - Kept:
    - the directory lock (`.archify-delivery-lock.json`, exclusive create, stale/concurrent/invalid/path-conflict handling;
      stale locks are removed by hand only);
    - the pending journal, written before render and removed only after a successful commit;
    - success and failure provenance;
    - path semantics, with the sidecar namespace probe;
    - bounded sidecar stems;
    - `check --require-provenance`;
    - the finalize final barrier.
  - Cut, with each item a stated deviation:
    - all of `atomic-output.mjs`;
    - the lock and journal identity re-checks;
    - quarantine, rollback recovery directories and `recover-output.mjs`;
    - `owned-temp-directory.mjs`;
    - creation of the legacy per-artifact lock (`check` and `finalize` still **read** `<stem>.delivery-lock.json`);
    - the `update` block everywhere;
    - finalize stage `command` = `["archify", …args]`;
    - `deliver --open` emits upstream's `{requested:true, status:'unsupported', target, method:null}` fallback and its stderr notice.

    survey-delivery §3 D1-D10 is the exact deviation list.
  - Deliver sequence, following upstream's stage order (A:4440-5171; survey-delivery §2.2):
    1. **`input`**: read the bytes and parse.
    2. **`prepare`**: validate the authored output path, resolve the output path, create the directory, resolve the
       provenance path.
    3. Acquire the directory lock.
    4. Write the journal. Upstream writes it **before** rendering (A:4738).
    5. **`render`**: `ArchifyNet.Render` in memory.
    6. **`check`**: `ArchifyNet.Check` on the bytes. A failure receipt carries `checker` with `checker.file = output`.
    7. **`receipt`**: build the receipt.
    8. **`commit`**:
       - write `<target>.archify-<guid>.tmp` beside the target;
       - swap it in with `File.Replace(tmp, target, backup)` when the target exists, else `File.Move(tmp, target)`. Retry
         briefly on sharing violations (IOException HResult 32 or 5), and note it with `ponytail:`;
       - write provenance the same way;
       - if the provenance write fails, roll back: `File.Move(backup, target, overwrite: true)` when a backup exists, else
         `File.Delete(target)`.
    9. Remove the journal, then the backup.
    10. **`release`**: delete the lock.

    **On any failure after the output is resolved**, port `recordDeliveryFailure` (A:1607-1872):
    - the journal stays (it is created if missing);
    - `<stem>.delivery.json` is written with `status:'failed'` **only if the target file exists**, otherwise the receipt
      says `provenance:'absent'`;
    - the lock is released.
- **Q6 — native paths.**
  - `NativeFs` (Task 4) provides `RealPath` (CreateFileW with `FILE_FLAG_BACKUP_SEMANTICS` + `GetFinalPathNameByHandleW`,
    stripping `\\?\` and `\\?\UNC\`) and `FileIdentity(volumeSerial, fileIndex, linkCount)` (GetFileInformationByHandle).
    Both are Windows P/Invoke.
  - Off Windows, `RealPath` falls back to the `ResolveLinkTarget` chain and identity to resolved-path equality. **Stated

## Review Focus

1. **A `--json` anywhere in `validate`, `deliver`, `finalize` or `inspect` argv turns an argument error into a JSON receipt
   with exit 2.** Everywhere else the plain message goes to stderr with exit 2 (A:7131-7138). Covered by the argument battery
   (19 receipt cases plus their human counterparts), Task 3.
2. **A failed deliver leaves the pending journal.** A later `check` fails closed with `delivery/provenance-failed`, until the
   next successful deliver removes the journal. Covered by Tasks 8 and 9.
3. **A stale directory lock (dead pid) gives `delivery/lock-stale`**, and the lock, journal, artifact and provenance stay
   byte-identical: no automatic takeover. Covered by Task 8.
4. **Sidecar names on NTFS fold case through the probe, not a string rule.** `WebApp.HTML` → `webapp.delivery.json`; a 240-char
   stem → a bounded hashed name. Covered by Task 5.
5. **Chromium missing → browser-check and visual-check report `skipped`, exit 2, and the fix names `archify install-browser`.**
   finalize then exits 2 with `failedStage: "browser-check"`. Covered by Tasks 10-12.
